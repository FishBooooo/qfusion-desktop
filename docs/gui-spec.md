# QFusion Desktop GUI 基线

状态：M0 空壳与 Mock 页面规范  
最后更新：2026-07-27

## 1. 技术与状态管理

- React + TypeScript 严格模式；
- Vite 构建；
- Ant Design 作为基础组件库；
- TanStack Query 管理后端状态；
- Zustand 仅用于必要的本地 UI 状态；
- Apache ECharts 用于后续金融图表；
- API 类型由 OpenAPI 生成，禁止手写漂移的服务端 DTO。

## 2. 信息架构

正式 GUI 包含：

1. Dashboard；
2. 股票分析工作台；
3. 板块分析工作台；
4. 回测实验室；
5. 数据中心；
6. 模型中心；
7. 设置。

股票工作台包含华尔街、量化、游资、综合、横向对比、证据与数据标签页。页面顶部始终显示当前状态、方向、周期、置信度、风险许可、数据新鲜度、主要触发和主要风险。

## 3. M0 页面

M0 只实现一个可验证的 Mock 股票分析页：

- 固定展示明确标记为 `SYNTHETIC_MOCK` 的合成证券数据；
- 显示三套独立模型与融合视图的占位结论；
- 显示 `PAPER_TRADE_ONLY`，不出现实盘操作；
- 通过 TanStack Query 调用 `/api/v1/health`；
- 后端不可达时保留 Mock 页面并显示“离线/缓存演示”，不得假装在线；
- 所有 Mock 时间使用带时区 ISO 8601 字符串。

## 4. 视觉与可访问性

- 中文为默认语言，内部契约字段可保留英文；
- 支持深色与浅色主题；
- 信息密度高但保持清楚的层级和留白；
- 颜色以外同时使用文字、图标或形状表达涨跌和风险；
- 键盘焦点可见；
- 小窗口下卡片可换行，不能依赖固定宽度；
- 金额、百分比和时间必须显式格式化。

## 5. 数据状态

界面统一显示：

```text
FRESH
DELAYED
STALE
MISSING
SYNTHETIC_MOCK
```

任何行动卡都必须同时显示数据截止时间和风险许可。数据过期或后端离线时禁止显示新的实时交易许可。

## 6. 非目标

M0 不实现真实 K 线、供应商连接、账户设置、交易预览、持仓或模型运算。任何看似金融结论的内容必须有醒目的 Mock 标识。
