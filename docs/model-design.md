# 多视角模型设计基线

状态：M0 契约设计，尚未实现交易模型  
最后更新：2026-07-27

## 1. 共同执行契约

一次分析先创建不可变 `AnalysisSnapshot`。编排器以同一个 `snapshot_id` 并行或顺序启动三套独立模型，但任何一套都不能读取其他模型的运行目录、结果 Repository 或内存对象。

每套模型必须：

- 独立产生完整策略；
- 按日内、5 日、20 日和 3 个月输出视图；
- 区分原始置信度与校准置信度；
- 引用证据 ID 和数据截止时间；
- 明确缺失数据、盲点和失效条件；
- 允许输出 `NO_TRADE`。

## 2. 华尔街模型 V0

采用确定性财务指标、事件与公告结构化抽取、估值规则、情景树和价格确认。自然语言模型只能解释已计算事实，不能计算估值、目标位、仓位或风险许可。

核心问题是市场预期与基本面现实之间是否存在可验证的预期差。

## 3. 量化模型 V0

先建立横截面因子评分和线性/逻辑回归基线，再考虑集成或树模型。必须进行时间切分、Walk-forward、样本外验证、概率校准，并把交易成本、滑点、公司行为、退市样本和数据修订纳入测试。

输出必须包含预期收益、概率、预测区间、因子贡献、预期成本和成本后净优势，不能压缩成单一总分。

## 4. 游资模型 V0

“游资式”仅代表合法的事件驱动、趋势、动量与情绪交易。采用主题强度、龙头排名、相对成交量、VWAP/锚定 VWAP、开盘结构和可回测情绪状态机。

状态转换必须由明确规则和数值特征决定，不由 LLM 自由判断。实现不得涉及虚假消息、对倒、虚假挂单、拉抬或未公开重大信息。

## 5. Fusion Packet

模型完整报告先通过 Pydantic/JSON Schema 验证，再投影为最小 Fusion Packet。Packet 至少包含：

- `contract_version`；
- `run_id`、`model_type`、`model_version`；
- `snapshot_id` 和目标永久标识；
- 分周期方向与校准置信度；
- 行动、交易计划摘要和风险摘要；
- 数据质量、证据引用和盲点。

融合入口必须拒绝：

- 不同 `snapshot_id`；
- 不同目标或未对齐周期；
- 未知契约版本；
- 缺失校准/质量字段；
- 重复模型类型；
- 未通过边界验证的数据。

详细决策见 [ADR-0004](adr/0004-versioned-fusion-packet.md)。

## 6. 融合模型

V0 采用规则门控、市场状态权重、分歧惩罚、数据质量惩罚和成本惩罚。禁止简单多数投票。融合分别输出战略、战术、执行和风险层结论，并明确一致点与分歧点。

## 7. 全局风险引擎

风险引擎独立于四套模型，由确定性规则实现。它检查数据新鲜度、流动性、价差、事件风险、账户暴露、回撤、成本和模型漂移，输出：

```text
APPROVED
APPROVED_WITH_REDUCED_SIZE
WATCH_ONLY
PAPER_TRADE_ONLY
REJECTED
```

模型一致看多也不能绕过风险否决。MVP 不存在自动实盘提交能力。

## 8. M0 Mock 的含义

M0 UI 中的方向、置信度和风险状态均为固定合成数据，只用于验证渲染、契约命名和离线提示。它们不是行情、预测、投资建议或模型测试结果。
